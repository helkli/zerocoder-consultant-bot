# Zerocoder Consultant Bot

ИИ-консультант «Алина» для сообществ ВКонтакте. Бот отвечает подписчикам на вопросы о курсах онлайн-университета [Zerocoder](https://zerocoder.ru) (зерокодинг, нейросети, внедрение ИИ в бизнес), помогает выбрать направление обучения и передаёт заинтересованных пользователей в отдел продаж.

Бот слушает новые сообщения сообщества через **VK Long Poll API**, генерирует ответы через **ProxyAPI** (OpenAI-совместимый endpoint) и отправляет их обратно пользователю. Все факты о Zerocoder бот берёт только из локальной базы знаний — модель не придумывает ничего сверх неё.

---

## Возможности

- **Диалоговый ИИ-консультант** — отвечает на вопросы о программах, сроках, форматах обучения и выборе направления.
- **База знаний в системном промпте** — `knowledge_base.md` подставляется в промпт при запуске; модель ссылается только на неё.
- **Память диалога** — для каждого пользователя хранится история последних `HISTORY_LIMIT` сообщений.
- **Команды** — `/start`, `/help`, `/reset`.
- **Разбивка длинных сообщений** — ответ длиннее лимита VK автоматически делится на части.
- **Устойчивость к сбоям** — переподключение при разрыве Long Poll, вежливый fallback при ошибке модели.
- **Работа за корпоративным прокси/антивирусом** — поддержка SSL CA-bundle, если Python не доверяет корневому сертификату машины.

## Как это работает

```
Подписчик ──сообщение──▶ VK Community
                            │
                      VkBotLongPoll
                     (опрашивает lp.vk.ru)
                            │
                        bot.py
                  ┌─────────┴──────────┐
                  │                    │
        история диалога          системный промпт
        (dict: user_id)    = alina_prompt.py (инструкции)
                  │        + knowledge_base.md (факты)
                  ▼                    │
              ProxyAPI ◀───────────────┘
        (OpenAI-совместимый endpoint)
                  │
            ответ модели
                  ▼
        VK: messages.send ──▶ Подписчик
```

1. `VkBotLongPoll` получает событие `MESSAGE_NEW` от новых сообщений сообщества.
2. `bot.py` отсекает служебные события (вложения, действия в беседе).
3. Команды `/start`, `/help`, `/reset` обрабатываются локально, без обращения к модели.
4. Обычное сообщение добавляется в историю диалога пользователя.
5. Формируется запрос к `chat.completions` *ProxyAPI*: системный промпт (Алина + база знаний) + последние сообщения диалога.
6. Ответ модели разбивается на части не длиннее 4000 символов и отправляется в VK.

## Быстрый старт

### 1. Подготовка сообщества ВКонтакте

1. Создайте или откройте сообщество (группу) ВКонтакте.
2. В настройках: **Управление сообществом → Сообщения** — включите «Сообщения сообщества» и «Сообщения сообщества: включены».
3. Зайдите в **Управление сообществом → Работа с API**, создайте ключ доступа с правами: *управление сообществом*, *сообщения сообщества*.
4. Включите Long Poll API и скопируйте числовой ID сообщества (раздел «Работа с API»).

### 2. Настройка ProxyAPI

Зарегистрируйтесь на [proxyapi.ru](https://proxyapi.ru) и получите API-ключ в личном кабинете. Выберите модель (подойдёт `gpt-4o-mini` или новее).

### 3. Установка и запуск

```bash
git clone git@github.com:helkli/zerocoder-consultant-bot.git
cd zerocoder-consultant-bot

python -m venv .venv
.\.venv\Scripts\activate        # Windows
# source .venv/bin/activate     # Linux / macOS

pip install -r requirements.txt
cp .env.example .env            # Windows: copy .env.example .env
```

Заполните `.env` реальными значениями:

```ini
PROXY_API_KEY=ваш_ключ_proxyapi
VK_TOKEN=токен_сообщества
VK_GROUP_ID=12345678
```

Запуск:

```bash
python bot.py
```

Бот начнёт отвечать на сообщения сообщества.

## Конфигурация

Все настройки — переменные окружения из `.env`:

| Переменная | По умолчанию | Описание |
|---|---|---|
| `PROXY_API_KEY` | — | Ключ API из личного кабинета ProxyAPI *(обязательно)* |
| `PROXY_API_BASE` | `https://api.proxyapi.ru/openai/v1` | Базовый адрес OpenAI-совместимого endpoint |
| `OPENAI_MODEL` | `gpt-4o-mini` | Модель для генерации ответов |
| `MAX_COMPLETION_TOKENS` | `300` | Максимум токенов ответа (ограничивает стоимость) |
| `HISTORY_LIMIT` | `10` | Сколько последних сообщений диалога помнить |
| `SSL_CA_BUNDLE` | пусто | Путь к CA bundle, если есть проблема с сертификатами (см. ниже) |
| `VK_TOKEN` | — | Ключ доступа сообщества ВКонтакте *(обязательно)* |
| `VK_GROUP_ID` | — | Числовой ID сообщества *(обязательно)* |
| `VK_API_VERSION` | `5.199` | Версия VK API |

## Устранение неполадок

### Ошибка `CERTIFICATE_VERIFY_FAILED` при запуске

На некоторых машинах HTTPS-трафик перехватывает антивирус или корпоративный прокси со своим корневым сертификатом. Python не читает системное хранилище Windows, поэтому корень нужно передать явно через `SSL_CA_BUNDLE`:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/get_ca.ps1
python scripts/build_ca_bundle.py
```

В `.env` укажите:

```ini
SSL_CA_BUNDLE=certs/ca.pem
```

Скрипт `get_ca.ps1` собирает цепочку сертификатов `api.vk.ru` в `certs/ca_store.pem`, а `build_ca_bundle.py` объединяет её со стандартными корнями (certifi) в `certs/ca.pem`. Директория `certs/` не коммитится в репозиторий (`.gitignore`).

> Примечание: `requests` 2.32+ игнорирует переменные `REQUESTS_CA_BUNDLE`/`CURL_CA_BUNDLE`, поэтому в `bot.py` сертификат для VK-сессии передаётся явно через `session.verify`.

### Длинные ответы не помещаются в сообщение VK

VK принимает сообщения до ~4096 символов. Лимит поставлен в 4000, а `split_message()` делит ответ на части по границам абзацев.

### Бот перезапускается при разрыве Long Poll

Это нормально: ошибки в цикле Long Poll логируются, после чего бот ждёт 3 секунды и переподключается.

## Ограничения

- База знаний статична: актуальность цен/условий ограничена содержимым `knowledge_base.md`.
- Память диалога живёт в оперативной памяти процесса и теряется при перезапуске бота.
- История хранится по ключу `user_id` — для бесед с несколькими участниками логика подписчика используется как у одного пользователя беседы.
- Бот работает только с личными сообщениями (`from_user`).

## Разработка

Ветки в репозитории выдержаны в Git Flow:

- `main` — стабильные, готовые к запуску версии.
- `develop` — интеграционная ветка разработки.
- `feature/*` — ветки под отдельные задачи (например, `feature/portfolio-release`).

Как внести изменение: создать ветку от `develop` → закоммитить → слить в `develop` → после проверки в `main`.
